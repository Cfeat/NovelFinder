# 拾页 · 小说推荐工具

本地小说发现工具：添加喜欢的小说，选择想看或不想看的元素，再获取有依据的推荐。界面参考起点中文网的红黑导航、分类侧栏和紧凑书目布局，使用拾页自己的名称和文字封面。

## 本次推荐机制研究（2026-10-07）

以下是平台公开资料能支持的机制，不能据此确定其当前内部模型、权重或完整业务规则。

| 平台 | 公开披露 | 本项目的应用 |
| --- | --- | --- |
| 起点 | [隐私政策 §2.8](https://acts.qidian.com/pact/qd_pact.html)，2026-09-09 更新：阅读记录、浏览、收藏、搜索、主动输入偏好等可用于个性化推荐，提供关闭选项 | 使用用户主动添加的喜好、元素偏好和已读／不感兴趣反馈；目前不采集阅读时长和页面浏览行为 |
| 七猫 | [算法团队架构文章](https://tech.qimao.com/qi-mao-suan-fa-tui-jian-yin-qing-jia-gou-yan-hua-zhi-lu/)，2023-10-27：多路召回、过滤去重、粗排、精排、重排与实验；属于历史公开架构 | 在小书库内计算相似作品、主动偏好、同作者信号；过滤后打分，再降低近期重复题材和作者的倾向 |
| 番茄 | [官方推荐验证期说明](https://fanqienovel.com/writer/zone/article/7659317147297923134)，2026-07-08：以推荐验证期观察读者反馈；公开信息不足以复现其内部模型 | 用明确标注的探索位置给陌生阅读元素展示机会；通过用户反馈排除作品。这是借鉴思路，没有模拟平台流量实验 |

选择这些机制，是因为小说的偏好不只取决于大分类：读者可能同时在意世界观、节奏、情感或作者。先解释相似点，再增加有限的探索候选，能兼顾贴合程度与多样性。单本“不感兴趣”仅排除该作品，不自动推断读者讨厌整个题材。

## 当前实现

- 初始快照含 757 条公开书目，与 16 本人工作品合并为 771 本；实际数量以界面为准。20 个阅读元素，分类、作者／书名搜索、平台筛选与分页。
- 喜好、主动偏好、屏蔽元素、最近 200 条反馈和探索模式保存在当前浏览器的 `localStorage`，不需要 ChatGPT 登录。最多保存 100 本喜好，可导出 JSON 备份；暂无跨设备同步和备份导入功能。旧服务端喜好没有自动迁入浏览器。
- **过滤**：按 ID 和规范化书名排除喜欢、已读、不感兴趣的作品；包含任一屏蔽元素的小说也不参与推荐，但仍可在全部作品浏览。
- **排序**：综合最相似喜好作品的加权标签余弦相似度、整体偏好覆盖率、主动偏好覆盖率与同作者信号。标签越少见，其共同点权重越高。有喜好时四项权重为 0.48／0.32／0.12／0.08；只有主动偏好时使用覆盖率 0.65／主动偏好 0.35。这些是本项目可调整的启发式权重，不是平台参数。
- **重排**：参考最近 4 本已选作品，对重复标签和作者施加软惩罚。更贴合不强制插入探索；平衡推荐每 6 个位置、多探索每 3 个位置尝试插入低匹配且带有陌生元素的作品，候选不足时保留匹配结果。探索仍遵守全部过滤规则。
- 推荐理由来自实际共同标签、主动选择或同作者关系。右侧推荐榜按原始匹配分排序，主推荐流包含多样性重排，所以顺序可能不同。无偏好时为书库精选，非平台人气榜。
- 当前没有跨读者行为矩阵、协同过滤、训练模型、全文分析或阅读时长预测。匹配分不是喜欢概率，也不代表作品质量。公开分类较粗或标签缺失时，推荐准确度会受限。
- 初始书库随应用加载；本地 D1 提供增量缓存和来源状态。手动检查更新至少间隔 1 小时，用数据库锁防止重复抓取；平台失败时保留旧数据。没有自动定时抓取。
- 从已收录书目添加喜好，也支持手动输入书名、作者及 1–6 个元素。晋江公开搜索仅在主动点击时请求，搜索冷却 10 秒；刷新和搜索服务仅接受本地主机及同源请求。
- 数据读取／保存失败显示错误，不覆盖原有本地书单；异常数据仍可原样导出。清除浏览器站点数据会丢失本地书单，请先备份。

## 本地运行

需要 Node.js 22.13+，在本目录运行：

```powershell
npm run install:ci
npm run dev
```

默认预览 `http://127.0.0.1:5173/`，端口占用时以终端输出为准。喜好和初始书库可以独立使用。首次使用增量缓存和公开平台搜索，需要初始化本地 D1：

```powershell
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_faulty_captain_marvel.sql
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_chilly_hedge_knight.sql
```

每个迁移仅执行一次，已初始化的本地数据库无需重复迁移。`npm start` 运行构建后的本地 Worker，同样监听 127.0.0.1。以上命令不发布网站，项目禁止自行创建或部署云端网站，详见 `AGENTS.md`。

```powershell
npm test
npm run typecheck
npm run build
```

20 项测试覆盖公开书目解析／去重、输入验证、推荐过滤、偏好、同作者、多样性、探索标记、本地画像校验及本地主机限制。`tests/api.integration.ps1` 属于保留的旧服务端喜好接口验证，不代表当前浏览器书架流程；当前界面不调用旧 `/api/favorites` 接口。

## 结构

- `components/novel-finder.tsx`：界面、分类搜索、喜好书架、反馈和偏好交互。
- `lib/novels.ts`：人工起步书库、匹配打分、推荐理由与多样性重排。
- `lib/reader-profile.ts`：浏览器画像格式与输入校验。
- `lib/catalog/`：公开网页解析、分类映射、去重与抓取。
- `data/public-catalog.json`：初始书目快照及来源状态。
- `db/catalog.ts`：本地 D1 增量缓存和同步锁。
- `app/api/catalog/`：本地书库读取、手动更新和晋江搜索。
- `lib/local-request.ts`：刷新／平台搜索的本地主机限制。
- `db/schema.ts` 与 `drizzle/`：数据库定义与版本化迁移。

来源为公开网页适配器，未接入合作 API，未绕过验证，不能保证全平台完整。人工起点书目及原站链接不算起点数据接入。页面变化、下架及网络限制会影响覆盖；缓存采集时间不证明作品仍上架，请通过原站链接核查。

书目记录包含书名、作者、分类、简介摘录、平台作品 ID、原站链接及采集时间。推荐标签由公开分类、原站标签映射；人工作品保留人工标签，不推测缺失信息。跨来源按规范化书名与作者合并，保留原人工作品 ID。只提供书目推荐，不获取小说正文或付费章节。

手动重新获取本地初始快照：

```powershell
node --experimental-strip-types scripts/sync-public-catalog.mjs
```

至少一个来源成功后才写入快照。运行后核查来源状态、测试和类型检查，再进行本地构建。
